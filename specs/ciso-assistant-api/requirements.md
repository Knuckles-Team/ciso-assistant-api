# CONN-CISO-ASSISTANT-API — Requirements

Governing spec: [spec.md](spec.md).

Each row is one requirement. A row names the file it touches and the test that proves it.

| ID | Requirement | Acceptance |
|---|---|---|
| `CONN-CISO-ASSISTANT-API-R001` | **SDK floor.** `pyproject.toml` must require `scion-sdk[mcp]>=0.5.6,<1.0.0`, the compatible renamed SDK release preserving the credential behavior introduced in scion-sdk 0.3.10, where `default_credential_resolver()` serves `env://` when `OPENBAO_TOKEN_REF` is unset. Caller chain: the `ciso-assistant-mcp` console script (`ciso_assistant_api.mcp_server:mcp_server`, line 79) -> `get_mcp_instance` (line 72) -> SDK `build_server("ciso_assistant_api")` -> `get_client` (`ciso_assistant_api/auth.py` line 53), whose secret resolution depends on the SDK floor declared in `pyproject.toml`. Shape: the floor is the `scion-sdk[mcp]` requirement in `pyproject.toml` dependencies and the `mcp` and `all` extras; `tests/test_credential_refs.py::test_sdk_floor_is_declared` parses the requirement with `packaging` and checks its range. | `tests/test_credential_refs.py::test_sdk_floor_is_declared` must pass. |
| `CONN-CISO-ASSISTANT-API-R002` | **Wiring.** `get_client` in `ciso_assistant_api/auth.py` must resolve `CISO_ASSISTANT_USERNAME_REF` and `CISO_ASSISTANT_PASSWORD_REF` through `resolve_secret_reference` with `OPENBAO_ADDR` set and no `OPENBAO_TOKEN_REF`. Caller chain: `ciso_assistant_api/mcp_server.py::register_server_surface` (line 32) passes `get_client` to `register_tool_surface` -> `get_client` (`ciso_assistant_api/auth.py` line 53) -> `_resolve_optional_secret` (line 120) -> `scion_sdk.credentials.resolution.resolve_secret_reference`. Shape: `get_client` reads `CISO_ASSISTANT_USERNAME_REF` and `CISO_ASSISTANT_PASSWORD_REF` through `scion_sdk.config.setting` and `_resolve_optional_secret`; the test sets `env://` references with `OPENBAO_ADDR` and no `OPENBAO_TOKEN_REF` and builds the client. | `tests/test_credential_refs.py::test_env_refs_resolve_with_openbao_addr_and_no_token_ref` must build a client through `get_client`. |
| `CONN-CISO-ASSISTANT-API-R003` | **Headless login.** `_ensure_token` in `ciso_assistant_api/api/api_client_base.py` must use a configured token without logging in; otherwise it must `POST /api/_allauth/app/v1/auth/login` with JSON `email` (or `username` when the identity has no `@`) and `password`, and use `meta.access_token` from the response as the API token. It must not call `/api/iam/login/`. Caller chain: any API tool call -> `Api` client method in `ciso_assistant_api/api/` -> `_auth_headers` (`ciso_assistant_api/api/api_client_base.py` line 152) -> `_ensure_token` (line 116), which posts the headless login when no token is configured. Shape: `_ensure_token` caches the token under `_token_lock` and posts JSON `email` or `username` plus `password` to `/api/_allauth/app/v1/auth/login` with the session in `api_client_base.py`; `tests/test_auth.py` covers the login and the configured-token paths. | `tests/test_auth.py::test_headless_login_returns_access_token` and `tests/test_auth.py::test_configured_token_skips_login` must pass. |
| `CONN-CISO-ASSISTANT-API-R004` | **Fleet name.** `pyproject.toml` declares `ciso-assistant-mcp` as the single `scion_sdk.connector` entry point. The content pack, the manifest `connector`, the fingerprints and the ingest binding all carry `ciso-assistant-mcp`. Proving test: `tests/test_fleet_name.py::test_connector_name_is_the_fleet_name`. Caller chain: the `ciso-assistant-mcp = ciso_assistant_api:connector` entry point in `pyproject.toml` -> `ciso_assistant_api/__init__.py::connector` (line 76) -> `IngestBinding` and `ConnectorContent` calls that carry the connector name. Shape: the name is a literal in `pyproject.toml` and the package calls; `tests/test_fleet_name.py` walks the package by AST and compares every `connector` keyword with the fleet name. | Every connector name in the package is `ciso-assistant-mcp`. |
